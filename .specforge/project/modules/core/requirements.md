# WI-0035 Investigation Plan

## 调查目标
对比需求文档 `doc/飞检现场管理系统_业务逻辑定稿_v1.14_最终干净版_开发输入.md`（9192 行）与安卓端实际实现 `fj-android/src/`，逐章节审查业务需求覆盖度，回答以下核心问题：

1. **页面覆盖度**：§44 列出的 10 个页面是否全部实现？每个页面的功能是否完整？
2. **业务流程完整性**：检查任务分配→执行→取证→提交→退回→修改的完整链路是否贯通？
3. **功能点覆盖度**：拍照、签名、离线同步、标准推荐、GPS 定位等功能是否实现？
4. **数据模型对齐**：WatermelonDB schema 是否覆盖后端 API 契约的所有实体？
5. **UI/UX 需求**：§45 今日检查统计、§55 问题篮子分类等具体页面要求是否满足？

## 调查范围
### 包含
- 需求文档中与安卓端相关的全部章节（§43-§60+，安卓端现场取证工具部分）
- 安卓端 `fj-android/src/` 全部 TypeScript/TSX 源码
- 后端 API 路由（仅核对接口契约对齐，不审查后端实现质量）

### 不包含
- 后端 Java 代码的内部实现质量
- iOS 端（本项目只有安卓）
- Web 管理后台
- 构建配置、CI/CD、部署流程（已在 WI-0001~0034 完成）

## 调查方法
1. **需求文档结构化提取**：逐章节阅读需求文档，提取每个业务需求点（功能需求 + 非功能需求 + UI 规范）
2. **代码实现审计**：逐文件审查安卓源码，提取已实现功能清单
3. **交叉对比**：将需求点与实现清单逐条对比，标注 ✅/⚠️/❌
4. **差距分析**：对每个未实现/部分实现的需求点，分析缺失原因和补全建议

## 预期产出格式
- **审查矩阵**：需求章节 → 需求点 → 实现状态（✅/⚠️/❌）→ 证据（代码位置）→ 差距说明
- **差距清单**：按优先级（P0 核心 / P1 重要 / P2 增强）排序的待补全功能
- **总体覆盖率评估**：百分比估算 + 关键瓶颈说明
