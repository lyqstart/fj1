# WI-0035 调查报告：安卓端业务需求覆盖度审查

## 调查结论

### 总体覆盖率

| 状态 | 数量 | 占比 |
|------|------|------|
| ✅ 已实现 | 23 | 34% |
| ⚠️ 部分实现 | 29 | 43% |

**总体评估**：安卓端 App 完成了约 **34% 的完整实现 + 43% 的部分实现**。核心骨架（导航/登录/数据层/同步引擎/照片压缩上传/取证页基本功能）已就位，但在**业务完整性**层面存在重大差距。

## 建议

### 建议拆分为以下 WI 序列推进补全：

| WI | 范围 | 优先级 | 预估复杂度 |
|----|------|--------|-----------|
| WI-A | 数据模型补全（issue_source/severity_status/standard_basis_status/capture_source 字段） | P0 | 中 |
| WI-B | 今日检查统计仪表板（5 类统计 + 3 操作入口） | P0 | 中 |
| WI-C | 检查表条目离线缓存 + 检查中页面完善 | P0 | 高 |
| WI-D | 提交校验体系（三级校验 + 阻断/强提醒/建议规则引擎） | P0 | 高 |
| WI-E | 问题取证页增强（字数校验 + 稍后处理 + 整改建议 + 问题分类） | P0 | 中 |
| WI-F | 问题篮子聚合统计 + 待完善原因标签 | P1 | 中 |
| WI-G | 标准推荐确认页（推荐引擎 + UI） | P1 | 高 |
| WI-H | 退回问题修改页 | P1 | 中 |
| WI-I | 照片大图查看器 | P1 | 低 |
| WI-J | 后端种子数据（项目 + 检查表 + 任务分配给 admin） | P0 | 低 |

### 建议执行顺序

```
WI-J（种子数据）→ WI-A（数据模型）→ WI-B（今日检查统计）→ WI-C（检查表缓存）
→ WI-E（取证增强）→ WI-D（提交校验）→ WI-F（问题篮子统计）
→ WI-G（标准推荐）→ WI-H（退回修改）→ WI-I（大图查看）
```

2. 后端 API 实现完整性未深入审查（仅核对接口契约对齐）
3. WatermelonDB schema 字段完整性基于 schema.ts 静态审查，未通过运行时验证
